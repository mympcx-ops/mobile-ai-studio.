# V3.2 — Independent Validation & Evidence Engine

## Purpose
Adds a phone-side validation evidence workflow after V3.1's local Tool Registry & Dependency Planner. A saved Prompt-to-Agent blueprint produces six required scenarios: normal operation, edge cases, failure handling, security boundaries, permission boundaries, and regression.

## Evidence workflow
- Record a declared Builder and a different declared Independent Validator.
- Record each scenario's outcome, observed result, evidence reference/description and timestamp.
- A readiness record is eligible only when all six categories are present, all have evidence and observed results, none is FAIL or BLOCKED, and the declared Validator differs from the Builder.
- Save evidence packs locally and export JSON.
- Record an explicit Owner readiness approval or rejection. Approval is a local readiness decision only.

## Trust limits
- This release does not execute tests, inspect evidence artifacts, authenticate Builder/Validator identities, or independently verify reviewer independence. Names are declarations only.
- Evidence is manually entered and can be inaccurate or fabricated; the UI must not label it as machine-verified.
- A PASS_WITH_EVIDENCE status means the local completeness rules were met, not that tests were actually run by this app or that the agent is safe.
- Owner readiness approval does not authorize installation, host access, shell execution, filesystem writes, model dispatch, agent activation, publishing or deployment.
- Quinn/Ollama, authenticated pairing, Tool Broker and PR #7 cryptographic pairing review remain separate gates. PR #7 stays draft/review-only and untouched.
- No protected Quinn or PoliAI runtime is modified.

## Local storage
- Reads Prompt-to-Agent drafts from `mobile-ai-studio-prompt-agent-v1`.
- Reads tool readiness proposals from `mobile-ai-studio-tool-proposals-v1` only as upstream planning context (no execution).
- Stores evidence packs in `mobile-ai-studio-validation-evidence-v1`.

## Validation
Dedicated Node tests cover missing evidence, evidence-required outcomes, same-person review, failed/blocked scenarios, Owner gating, explicit trust limits, and offline asset wiring. GitHub Actions results must be inspected before reporting CI status.
