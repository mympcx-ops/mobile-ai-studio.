# V3.5 — Agent Arena, Identity Studio & Agent Exchange

## Purpose
Extend the V3.4 phone-first foundation without replacing the canonical fleet, workflow orchestrator, Agent Assurance, or protected Quinn/PoliAI runtimes.

## Delivered in this branch
- Agent Arena roster view for the existing 29 agents and six oversight roles.
- Stable default visual identity per agent; Owner-editable palette and avatar form stored locally and separately from agent behavior.
- Ten-floor architecture registry. Floors 0–4 preserve the existing command/operations, Music, Media and Racing organization. Floors 5–9 are explicitly proposed additions; no production agents or reporting relationships are silently created.
- Portable JSON blueprint export with SHA-256 integrity fingerprint.
- Import-side schema, security-flag and fingerprint verification; imported packages are local drafts only.
- Export excludes credentials, private memory, granted tools, executable code and activation authority.
- Regression tests for package integrity, unsafe flags, identity constraints and floor preservation.

## Arena truth labels
The Arena is a phone-local roster and visual identity preview. It does not imply agents are connected, communicating, thinking, executing or competing. Those capabilities require a future authenticated PC runtime and separately approved simulation harness. Appearance is never evidence of capability, test completion or certification.

## Portable package contract
Format: mobile-ai-studio-agent-package/1. Package type: BLUEPRINT_ONLY.
- Contains the agent's role description and visual identity.
- Tool requirements are empty in this initial exchange format. Recipients rebuild and review requirements locally through the Tool Registry.
- Memory template is empty; no private memory or conversation history is exported.
- Credentials, private memory, executable content, execution, activation, external writes, publishing and deployment flags must all be false.
- SHA-256 covers canonical JSON payload excluding the integrity object.
- Import validates format, required fields, allowed identity options, security flags and fingerprint.
- Import never overwrites canonical agents, grants tools, installs dependencies, activates or deploys an agent.

## Marketplace boundary
This release implements local portable export/import only. Public listings, accounts, payments, ratings, remote update channels and hosted distribution are future services, not available features. Until a separately reviewed marketplace exists, packages are shared manually through a trusted channel. SHA-256 detects content changes but does not authenticate the creator.

The 29-agent fleet and six Floor Director / Independent Validator oversight roles remain the baseline. Existing managers and reporting assignments must be preserved. New floor roles require Owner review and independent validation design before joining the canonical fleet.

## Governance / Constitution
The Owner remains final authority. Quinn is the proposed orchestration/development intelligence, subject to later authenticated integration. Builders cannot certify their own work. Independent validators must be separate from builders and review evidence. No self-granted permissions, silent production edits, automatic deployment or bypass of Owner approval. Consequential changes require audit records and rollback plans.

## Future gates
Live PC/Quinn/Ollama connectivity, real agent activity, arena competition, model-powered training, digital twins, autonomous repair execution, hosted marketplace, payments, ratings, update subscriptions, creator signatures, environment-specific imported-agent certification and independent test execution are not implemented by this branch.

## Acceptance checks
1. Existing Home, Command Center, Galaxy, Projects, Agents, Validation and V3.4 workflows remain.
2. Arena renders canonical roster without changing lifecycle status.
3. Stable default visual identities and local Owner edits persist.
4. Export contains no credentials, private memory, tool grants or executable permissions.
5. Tampered or unsafe packages are rejected.
6. Imported packages remain drafts and do not overwrite canonical agents.
7. New assets enter offline shell and cache version increments.
8. Node regression suite passes; Android physical-device acceptance remains a separate gate.
