# V2.0 — Offline desktop import validation contract

## Scope

This milestone adds a pure Node.js validation module for the phone's existing JSON export format. It is an intake gate, not an importer service. It has no filesystem, process, network, socket, model-runtime, or agent-execution behavior.

## Validation performed

- Enforces the exact export envelope format and a 1 MiB input limit.
- Rejects malformed JSON, unexpected top-level fields, unsafe object keys, and malformed timestamps.
- Requires the current blueprint package type, version, pending-validation lifecycle, provenance, and canonical seven-check acceptance list.
- Recomputes SHA-256 using the same sorted-key canonical JSON algorithm as the phone UI and rejects mismatches.
- Enforces least-privilege permission flags and denies execution, dispatch, external writes, publishing, deployment, and secrets.
- Checks the agent instruction capability contract and output contract.
- Validates any attached review records are package-bound, distinct from the builder identity, complete, and still pending Owner approval.

## Read-only desktop command

After cloning the repository on the Windows PC, validate one downloaded export without importing it:

```powershell
node .\desktop-import\validate-file.cjs "$env:USERPROFILE\Downloads\agent-package.json"
```

The command opens the selected file read-only, enforces the 1 MiB limit, prints a validation report, and returns a non-zero exit code for rejected files. It does not copy, stage, rename, install, or execute the package.

## API

```js
const fs = require("node:fs");
const { validateEnvelope } = require("./desktop-import/validator.cjs");

// Caller is responsible for safely selecting and reading a bounded file.
// The validator itself never reads or writes files.
const result = validateEnvelope(fs.readFileSync("agent-package.json", "utf8"));
if (!result.valid) {
  // Reject and show result.code/result.message.
} else {
  // Keep as VALIDATED_UNTRUSTED_PROPOSAL in a quarantine/staging workflow.
  // Do not install, activate, dispatch, publish, or execute.
}
```

## Critical trust limits

- SHA-256 is an integrity check, not a digital signature. It does not authenticate the package author, reviewer, device, or transfer channel.
- Reviewer IDs and evidence references are declarations supplied by the phone UI; this validator does not authenticate them or retrieve evidence.
- A passing result is not Owner approval and does not authorize activation.
- The returned status is deliberately `VALIDATED_UNTRUSTED_PROPOSAL`; `installationAuthorized` and `executionAuthorized` are always false.
- This module does not create a quarantine folder, write a registry, change agent lifecycle state, or connect to Quinn/Ollama.
- A future desktop importer must separately implement bounded file acquisition, path-safe quarantine storage, duplicate/replay handling, authenticated Owner approval, independent review, audit logging, and Windows host security controls. It must not bypass this validator or convert a pass into activation.

## Verification

The accompanying Node test suite covers valid intake, malformed and oversized input, tampering, permission escalation, unsafe safety flags, transfer-policy escalation, acceptance-check manipulation, unexpected fields, prototype-pollution keys, and invalid review records.
