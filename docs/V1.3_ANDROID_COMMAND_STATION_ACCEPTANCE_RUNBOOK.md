# V1.3 Android Command Station Acceptance Runbook

Status: EXECUTION GUIDE ONLY — no physical-device test results are claimed.

## Test target
- Use a dedicated development deployment of `feature/v1.2-live-command-station`.
- Do not use or overwrite the live/main deployment.
- Record Android model, Android version, Chrome version, deployment commit, test date and tester.
- Export a backup before testing destructive recovery cases.

## A. Install and layout
- [ ] Open the development deployment in Android Chrome.
- [ ] Install the PWA / add it to the home screen.
- [ ] Launch from the home-screen icon and verify standalone display.
- [ ] Check portrait layout, safe areas, bottom navigation and modal close controls.
- [ ] Check narrow viewport behavior and horizontal overflow.
- [ ] Rotate the device and confirm controls remain reachable.

## B. Existing-version regression
- [ ] Confirm V1.0 projects, notes and custom agent drafts remain present.
- [ ] Confirm V1.1 tasks, communications, approvals and validation records remain present.
- [ ] Confirm the 29-agent directory and six oversight roles remain visible.
- [ ] Confirm every role is still labelled PLANNED / NOT_RUN.
- [ ] Confirm no screen implies that an agent or backend is running when it is not.

## C. V1.2 command station
- [ ] Open each floor dashboard and role workspace.
- [ ] Create a local task, edit it, complete it and reopen it.
- [ ] Enable local Owner HOLD and confirm new local task/proposal transitions are blocked.
- [ ] Disable local HOLD and confirm normal local planning resumes.
- [ ] Verify the UI clearly says phone-side HOLD does not stop PC processes.
- [ ] Create a communications draft and confirm LOCAL DRAFT / NOT SENT.
- [ ] Record a proposal approval/rejection and verify no action is executed.
- [ ] Verify dependency blocking and reviewer/builder name guard behavior.
- [ ] Verify the event timeline and executive counts are labelled as local records, not live telemetry.

## D. V1.3 phone-side behavior
- [ ] Test typed command parsing for supported local navigation/status commands.
- [ ] Test voice command permission denial, grant, unsupported browser and interruption.
- [ ] Confirm voice commands do not transmit audio or commands to the PC.
- [ ] Test local notification permission and a local test notification where supported.
- [ ] Confirm remote push is labelled NOT CONFIGURED.
- [ ] Confirm PC, Quinn, Ollama and telemetry remain NOT CONNECTED until authenticated observations exist.
- [ ] Confirm manual observations are labelled unverified.

## E. Backup, persistence and offline
- [ ] Export a backup and inspect that it contains only approved local app data.
- [ ] Import the backup into a controlled test state and verify round-trip recovery.
- [ ] Confirm credentials, pairing secrets and PC files are not included.
- [ ] Close and reopen the PWA; verify expected local records persist.
- [ ] Reload after service-worker update and verify the new shell is active.
- [ ] Test offline launch after a successful online load.
- [ ] Confirm unavailable network/backend states do not appear healthy or connected.

## F. Bridge security UI boundary
- [ ] Confirm no real device pairing is offered as completed.
- [ ] Confirm no credential, token or secret is shown in the UI or stored in localStorage.
- [ ] Confirm no shell, PowerShell, arbitrary path, URL fetch or execute control exists.
- [ ] Confirm all approvals remain records only and no task is remotely dispatched.

## Evidence capture
For each test, record PASS, FAIL, BLOCKED or NOT APPLICABLE, plus concise steps and screenshots with secrets/personal data redacted. Record browser console errors and service-worker state when relevant.

## Exit criteria
Acceptance is complete only when all applicable tests have evidence, regressions are resolved, backup/restore is demonstrated, and a reviewer other than the feature author signs the results. A test plan or checklist with no recorded results is not acceptance evidence.
