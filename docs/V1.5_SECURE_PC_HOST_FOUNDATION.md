# V1.5 Secure PC Host Foundation

Status: POLICY AND TEST FOUNDATION ONLY. No PC listener, HTTP server, WebSocket server, TLS termination, device pairing, credential issuance, persistent replay store, telemetry endpoint, model connection, or remote execution is implemented.

## Purpose
Prepare a fail-closed startup policy for the future PC-hosted bridge. The Android app remains the only user-facing command station. The PC is a backend host only. Quinn/Ollama remain disconnected until a separately reviewed integration phase.

## New files
- `bridge/host-policy.cjs`: pure configuration evaluator. It does not open sockets or perform cryptography.
- `tests/host-policy.test.cjs`: policy tests for disabled-by-default behavior, loopback-only binding, valid port ranges, required security controls, Owner approval, and permanently disabled dispatch/execution.
- CI runs the host policy tests with the existing contract and simulator suite.

## Startup policy
A future service may not even be considered for startup unless all of the following are true:
1. Explicit host enablement.
2. Loopback-only bind address (`127.0.0.1`, `::1`, or `localhost`) for the initial local development phase.
3. Valid explicit port.
4. TLS configured and verified by the actual transport implementation.
5. Authenticated device middleware backed by server-issued, revocable device credentials.
6. Durable, atomic replay protection shared across service restarts.
7. Redacted append-only audit sink.
8. Explicit Owner approval recorded for that exact host configuration.

Any missing control blocks policy. Public wildcard and LAN binds are rejected. Agent dispatch and remote execution are forbidden regardless of the supplied configuration.

## Critical distinction
`evaluateHostConfig()` is only a pure policy check. `allowed: true` means the supplied configuration values satisfy this reference checklist; it does not prove that TLS, authentication, durable storage, audit integrity, or Owner identity are real. The state is deliberately named `POLICY_CHECKS_SATISFIED_NOT_STARTED`. There is no listener and no connection.

## Required work before a real PC host
- Independently review the protocol and host threat models.
- Select a maintained server/runtime stack and pin dependencies.
- Implement TLS with certificate validation and a documented local trust/bootstrap flow.
- Implement pairing with high-entropy one-time challenges, short expiry, rate limits, explicit phone confirmation, server-issued per-device credentials, revocation and rotation.
- Store credentials in OS-protected storage; never expose secrets to browser localStorage or logs.
- Implement durable atomic nonce/replay protection with bounded retention and fail-closed behavior.
- Add rate limiting, request size/time limits, strict schemas, redacted append-only audit events and safe error handling.
- Expose only read-only health observations initially; distinguish unavailable, stale and live observations.
- Test LAN isolation, IPv4/IPv6 binding, DNS rebinding, CSRF/origin policy, TLS downgrade, replay after restart, credential revocation, clock skew, resource exhaustion and malformed requests.
- Run Android physical-device acceptance and independent security review.
- Obtain Owner approval before enabling any listener or connecting Quinn/Ollama.

## Release boundary
No merge, publication, deployment, PC listener, real device pairing, agent activation, model access or execution is authorized by this phase.
