# V3.4 Agent Assurance & Self-Repair Planner

## Purpose
Add a phone-first, offline assurance layer to Mobile AI Studio. A saved Prompt-to-Agent blueprint can generate a 15-family validation suite and a local evidence record.

## Coverage
Identity and role; instruction following; tool selection; task execution; reasoning and uncertainty; safety; failure recovery; communication and reporting; regression; adversarial/prompt-injection resistance; multi-step planning; memory integrity; performance/resource limits; agent collaboration and handoffs; permissions and authority.

## Evidence and readiness
Every outcome requires an observed result and an evidence reference. A readiness record requires all 15 categories completed, no FAIL or BLOCKED results, and distinct Builder and Validator declarations. The current phone-only identity check is self-declared and does not authenticate either person.

## Repair proposal loop
Failures produce bounded repair suggestions and a retest list containing the failed category plus regression. Suggestions are proposals only. No source files, agent instructions, permissions, host files, or production systems are changed by this module. A human must review and approve a repair before implementation in an isolated environment; the changed agent must then rerun affected tests and regression before independent validation and Owner readiness review.

## Safety boundaries
- No agent runtime, tool, shell, host filesystem, Quinn connection, or model dispatch is invoked.
- Evidence is manually entered and is not independently authenticated.
- Builder cannot satisfy the independent Validator requirement using the same declared identity.
- Owner readiness approval is not activation, deployment, publish, or host-access authorization.
- Existing V3.2 validation and V3.3 workflow modules remain intact.

## Phone integration
The module is loaded after existing planning and validation modules, injected into the Agent Directory, and included in the offline service-worker cache.
