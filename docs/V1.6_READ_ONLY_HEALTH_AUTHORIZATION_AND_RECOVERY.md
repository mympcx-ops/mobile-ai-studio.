# V1.6 — Read-Only Health Authorization and Connection Recovery

**Status:** DESIGN ONLY / NOT IMPLEMENTED  
**Default runtime state:** DISCONNECTED  
**Maximum proposed phone permission:** READ_STATUS / READ_HEALTH only.

## 1. Purpose

Define the smallest useful first connection after secure device pairing: the phone may request a narrowly scoped health snapshot from the PC host. This is not a live telemetry implementation, agent console, project browser, or remote-control channel.

The current simulator's synthetic status must remain clearly labeled SIMULATOR_ONLY. A future real host must never reuse synthetic data while presenting it as live PC status.

## 2. Permission model

The first enrolled device receives only READ_STATUS and READ_HEALTH. No other scopes are implied. In particular, WRITE_PROJECT, READ_FILES, READ_TELEMETRY, SEND_MESSAGE, PROPOSE_ACTION, DISPATCH_AGENT, ADMIN_PAIRING, and EXECUTE are not granted by default. A later feature needing another scope requires a separate specification, threat review, tests, and explicit Owner approval.

The host must derive the authenticated principal from verified credential middleware. It must never accept deviceId, scopes, ownerApproved, or authenticated from request JSON as authority.

## 3. Health response schema

A future response should be versioned and minimal:
- source: exactly LIVE_HOST or SIMULATOR_ONLY
- hostInstanceId: opaque, non-secret host identifier
- protocolVersion: negotiated protocol identifier
- connectionState: CONNECTED, DEGRADED, or DISCONNECTED
- serviceState: RUNNING, STOPPED, STARTING, or UNKNOWN
- quinnState: CONNECTED, DISCONNECTED, NOT_CONFIGURED, or UNKNOWN
- ollamaState: CONNECTED, DISCONNECTED, NOT_CONFIGURED, or UNKNOWN
- modelState: AVAILABLE, UNAVAILABLE, NOT_CONFIGURED, or UNKNOWN
- observedAt: host-generated timestamp
- sequence: monotonically increasing host sequence number where durable storage permits
- staleAfterMs: explicit freshness threshold

Do not expose local usernames, absolute file paths, environment variables, process command lines, tokens, private network details, prompt contents, or unrelated application data.

Telemetry is excluded from the initial health scope. Any later telemetry endpoint requires its own schema, privacy review, data minimization rules, scope, and retention policy.

## 4. Freshness and truthfulness

- Host generates observedAt; phone does not supply it.
- Phone displays age of the last authenticated snapshot.
- A snapshot older than staleAfterMs becomes STALE and must not be presented as current.
- A failed refresh changes state to DEGRADED or DISCONNECTED; it does not retain a green/connected state indefinitely.
- Missing fields are UNKNOWN, not assumed healthy.
- Simulator responses always show a visible SIMULATOR label and synthetic-data warning.
- UI distinguishes transport connected from Quinn/Ollama actually connected.
- A successful HTTP response does not prove the underlying model is ready.

## 5. Request authorization sequence

For every status request, a future host must:
1. Validate transport security and host identity.
2. Authenticate the device credential.
3. Resolve the principal from trusted server-side credential state.
4. Check that the credential is active, not expired, revoked, or suspended.
5. Verify READ_STATUS or READ_HEALTH scope as appropriate.
6. Enforce request size, rate, timeout, and replay controls.
7. Read only the allowlisted health provider.
8. Redact and validate the response schema.
9. Write a redacted audit event.
10. Return the response with no side effect.

The host must not invoke arbitrary shell commands, PowerShell, process launch, filesystem traversal, or model prompts to answer a health request.

## 6. Connection lifecycle and recovery

| State | UI behavior | Allowed next step |
|---|---|---|
| DISCONNECTED | Neutral disconnected indicator; no cached data shown as live | User initiates connect |
| VERIFYING_HOST | Show identity verification in progress | Verified or rejected |
| AUTHENTICATING_DEVICE | Show authentication in progress | Authenticated or rejected |
| CONNECTED_READ_ONLY | Show timestamped health snapshot and read-only badge | Refresh or disconnect |
| DEGRADED | Show last snapshot age and exact failure category | Retry with backoff |
| STALE | Clearly label cached snapshot stale | Refresh or disconnect |
| REVOKED | Stop requests and clear session material | New Owner-approved pairing |
| AUTH_FAILED | No retry storm; show generic actionable message | User retry after bounded delay |
| HOST_UNAVAILABLE | Make no live status claim | Retry with backoff |
| DISCONNECTED_BY_USER | Clear session state | User reconnects |

Recovery rules:
- On app restart, process death, phone sleep/wake, Wi-Fi change, PC sleep/wake, or host restart, phone begins DISCONNECTED or VERIFYING_HOST. It must not assume the old session remains valid.
- Reconnect uses bounded exponential backoff with jitter and a maximum retry budget.
- Successful reconnect performs fresh host identity verification and device authentication before health data is shown.
- If host identity changes unexpectedly, stop and require explicit user verification; never silently accept the new identity.
- If credential is revoked or expired, clear session tokens and return to pairing-required state.
- If response sequence moves backward or response is malformed, reject it and mark state DEGRADED.
- Manual disconnect stops retries immediately.
- Recovery must not trigger task dispatch, agent wake, model prompts, or any write action.

## 7. Privacy and data retention

- Health snapshots are ephemeral by default and remain in memory only for the current view/session.
- Any future local history must be explicitly enabled, minimally scoped, time-limited, and deletable.
- Never store credentials alongside health snapshots.
- Do not transmit health data to analytics or third-party services.
- Exported diagnostics must be opt-in, redacted, and previewed before sharing.

## 8. Acceptance test matrix for a future implementation

| Test | Expected result |
|---|---|
| Unpaired phone requests status | DENY / PAIRING_REQUIRED |
| Expired credential requests status | DENY / CREDENTIAL_EXPIRED |
| Revoked credential requests status | DENY / DEVICE_REVOKED |
| Credential lacks READ_STATUS | DENY / INSUFFICIENT_SCOPE |
| Request JSON claims Owner approval | Claim ignored; server-side state decides |
| Request contains shell/path/command | Reject schema; no process starts |
| Quinn not configured | quinnState = NOT_CONFIGURED |
| Ollama offline | ollamaState = DISCONNECTED |
| Host snapshot exceeds freshness threshold | UI marks STALE |
| Phone resumes after sleep | Re-authenticate before showing fresh state |
| PC restarts | Phone detects unavailable host and recovers safely |
| Host certificate/fingerprint changes | Stop; require explicit verification |
| Replay or out-of-order response | Reject and audit redacted failure |
| User disconnects | No background retry or side effect |
| Simulator supplies synthetic response | Persistent SIMULATOR_ONLY label |

## 9. Security and release gates

- [ ] Physical Android tests across app restart, background/foreground, network changes, and offline conditions.
- [ ] Server-side authorization tests for every scope and lifecycle state.
- [ ] Stale-data, clock-skew, sequence rollback, and malformed-response tests.
- [ ] Proof that health reads have no filesystem, shell, process, model, or write side effects.
- [ ] Redaction and privacy review of every health field.
- [ ] Independent security review of the actual implementation.
- [ ] Owner approval before any live read-only connection trial.

**Current disposition:** no live health endpoint exists. No phone-to-PC connection has been tested. The V1.4 simulator remains synthetic and isolated. All release gates remain open.
