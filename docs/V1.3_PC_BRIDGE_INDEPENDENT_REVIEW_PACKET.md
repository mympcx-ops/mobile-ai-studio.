Status: REVIEWER HANDOFF — NOT AN INDEPENDENT REVIEW OR SECURITY APPROVAL.

## Review boundary
Review the protocol contract, threat model, tests and release gates on the feature branch. Do not enable a listener, pair a phone, connect Quinn/Ollama, or authorize remote execution as part of this review.

## Artifacts to inspect
- `bridge/contract.cjs` — reference request validator and in-memory nonce ledger.
- `tests/bridge-contract.test.cjs` — automated contract tests.
- `docs/V1.3_PC_BRIDGE_PROTOCOL_AND_SECURITY_TESTS.md` — protocol and server requirements.
- `docs/V1.2_SECURE_PC_BRIDGE_ARCHITECTURE.md` — architecture and threat model.
- `.github/workflows/bridge-contract-tests.yml` — CI invocation.

## Required reviewer checks
1. Confirm the server never trusts device identity, scopes, roles or approval claims supplied by the phone.
2. Confirm every action is explicitly allowlisted and each action has a narrow schema and scope.
3. Confirm arbitrary shell, PowerShell, Python, filesystem paths, URL fetches, generic tool invocation and execution actions are rejected.
4. Inspect timestamp validation, nonce uniqueness, replay behavior, capacity exhaustion and fail-closed handling.
5. Verify malformed JSON, unexpected object shapes, oversized payloads and unknown protocol versions are rejected before any handler runs.
6. Check that errors and audit records cannot leak credentials, pairing challenges or sensitive project content.
7. Confirm a future production listener requires authenticated TLS, revocable device credentials, server-side authorization, durable atomic replay protection, rate limits and append-only redacted audit events.
8. Confirm phone-side HOLD and approval records cannot be mistaken for PC-enforced safety controls.
9. Confirm no test or documentation implies that the reference validator is a production security boundary.
10. Identify missing tests, exploitable edge cases and required remediation before any integration work proceeds.

## Required review evidence
The independent reviewer should provide:
- Reviewer identity and relevant review basis.
- Exact commit SHA reviewed.
- Files and test commands examined.
- Findings with severity, reproduction steps and affected paths.
- Explicit disposition: APPROVED FOR NEXT DEVELOPMENT PHASE, CHANGES REQUIRED, or REJECTED.
- Confirmation that no live listener, device pairing or remote execution was enabled during review.

The reviewer must not be the author of the implementation being reviewed. A self-review, automated CI pass or Owner approval is not a substitute for independent review.

## Hard stop conditions
Stop and request remediation if any of the following is found:
- An untrusted request can select arbitrary commands, paths, URLs or tools.
- Authorization can be satisfied by request-supplied scopes or identity.
- Replay storage is unavailable but a request is accepted.
- A phone approval or HOLD is treated as authorization or a PC kill switch.
- Secrets appear in source, logs, localStorage, backups or error output.
- A production listener can bind to a public interface without authenticated transport and explicit Owner configuration.
