# V1.4 PC Bridge Integration Foundation

Status: LOCAL SIMULATOR ONLY — no PC service, listener, pairing, tunnel, live telemetry, model access, filesystem access or remote execution is implemented.

## Goal
Exercise the V1.3 request/authorization contract end-to-end inside a deterministic Node.js test process before designing a real PC-hosted service. The Android PWA remains the only user-facing command station; the PC remains the future backend host.

## Included
- `bridge/simulator.cjs`: in-process request simulator using the shared V1.3 contract validator.
- `tests/bridge-simulator.test.cjs`: integration-style tests for simulated status, synthetic project metadata, proposal-only actions, authentication, scope checks, replay rejection, capacity limits and disabled operations.
- CI executes every `tests/*.test.cjs` test file on Node.js 22.

## Simulator behavior
- `READ_STATUS` returns explicit `SIMULATOR_ONLY`, `NOT_CONNECTED` and `NOT_AVAILABLE` labels. It never reports real PC, Quinn, Ollama, GPU, CPU or agent health.
- `READ_PROJECT` returns synthetic fixture metadata only; it never reads a PC project or filesystem.
- `PROPOSE_TASK` and `PROPOSE_ACTION` create bounded in-memory records marked `PROPOSED_NOT_DISPATCHED`.
- `ADMIN_PAIRING` is rejected as not implemented.
- Unknown actions, invalid schemas, unauthenticated principals, wrong device identities, missing scopes and replayed nonces are rejected by the shared validator.

## Hard boundaries
The simulator has no HTTP server, WebSocket server, socket binding, tunnel, file access, model API, hardware telemetry, durable storage, credential issuance, Android secret storage, agent dispatch or execution path. Its in-memory nonce ledger is test scaffolding only and is not a production replay defense. A `simulation: true` response is never evidence of a real connection.

## Run locally
From the repository root with Node.js 22:
```sh
node --test tests/*.test.cjs
```
