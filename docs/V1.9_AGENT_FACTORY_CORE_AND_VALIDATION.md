# V1.9 — Agent Factory Core and Independent Validation Contract

**Status:** IMPLEMENTED CORE LIBRARY + AUTOMATED TESTS  
**Scope:** deterministic agent blueprint packaging and validation contracts.  
**Not included:** model-powered generation, PC runtime, agent activation, task dispatch, tool execution, or Quinn/Ollama connectivity.

## What the factory does

- Reads an agent from the canonical 29-agent catalog supplied by the caller.
- Builds a versioned blueprint package with builder attribution, acceptance checks, and a SHA-256 integrity fingerprint.
- Rejects unknown agent IDs, identity/floor/manager changes, lifecycle changes, forged validation status, malformed fields, and unsafe permission profiles.
- Requires an independent reviewer ID distinct from the builder ID.
- Requires every acceptance check to pass and evidence references/descriptions to be supplied.
- Records review as PASS_RECORDED_PENDING_OWNER_APPROVAL; it never activates the agent.

## Files

- agent-factory/contract.cjs — dependency-free Node.js factory and validation contract.
- tests/agent-factory.test.cjs — automated positive and negative tests.

## Factory lifecycle

CANONICAL_AGENT → BUILT_PENDING_INDEPENDENT_VALIDATION → PASS_RECORDED_PENDING_OWNER_APPROVAL

Failures remain blocked. The SHA-256 fingerprint detects package changes relative to the generated package; it is not a digital signature, authentication mechanism, or security boundary.

## Mandatory restrictions

- The canonical agent ID, name, floor and manager are preserved.
- Agent lifecycle remains PLANNED; validation starts NOT_RUN.
- The builder cannot self-assert validation.
- Local write, external network, execution, publishing, deployment, agent dispatch, shell, PowerShell, process launch, arbitrary filesystem access and credential access are prohibited.
- Reviewer identity is supplied by the caller and is not authenticated; evidence references are recorded but not independently fetched or verified.
- Owner approval is still required for any future activation. This release contains no activation function.

## Validation

Run with Node.js 22:

```sh
node --test tests/*.test.cjs
```

These tests validate the library contract only. They do not validate a running agent, model behavior, PC, Android, Quinn, Ollama, or a live security boundary.
